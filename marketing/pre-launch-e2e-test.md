## Намерена и поправена грешка

По време на Step 12 и сценариите от 24.3 излезе дефект, който не се вижда при
платен трафик и точно затова е опасен.

### Симптом

Посещение с referrer от Google (органично търсене) и посещение с referrer от
чужд сайт и двете се класифицираха като:

```
source_category = direct
```

При това самият referrer се записваше правилно (`referrer = google.com`).

### Причина

`app.js`, функцията `currentTouch()`, записва в `touch.referrer` **вече само
домейна**:

```js
var host = refHost(document.referrer);              // 'google.com'
touch.referrer = (host && !isOwnDomain(host)) ? host : '';
touch.source_category = classify(touch);
```

`classify()` след това пак минава през `refHost()`:

```js
function classify(touch) {
  var host = refHost(touch.referrer);               // refHost('google.com')
  ...
}
```

А старият `refHost` приемаше само пълен адрес:

```js
function refHost(referrer) {
  if (!referrer) return '';
  try { return new URL(referrer).hostname.replace(/^www\./, ''); } catch (e) { return ''; }
}
```

`new URL('google.com')` хвърля — няма схема. Значи `host` оставаше празен,
стъпка 4 от класификацията (тази по referrer) не се задействаше никога и
всичко падаше до `direct`.

### Обхват на щетата

| Трафик | Засегнат |
|---|---|
| Google Ads (`gclid`, `utm_source=google&utm_medium=cpc`) | **не** — излиза на стъпка 1, преди referrer-а |
| Meta Ads с UTM | **не** — стъпка 2 |
| Какъвто и да е трафик с UTM | **не** — стъпка 3 |
| Органично търсене в Google | **да** → отчиташе се `direct` |
| Referral от чужд сайт | **да** → `direct` |
| Органичен Instagram / Facebook | **да** → `direct` |

Тоест ресторантската реклама е била проследявана коректно, но всяка органична и
препратена заявка е влизала в CRM и в tracker-а с грешен източник. Това щеше да
изкриви точно сравнението „плащаме ли си рекламата спрямо това, което идва
безплатно“.

### Поправка

`refHost` вече приема и пълен адрес, и само домейн:

```js
function refHost(referrer) {
  if (!referrer) return '';
  try { return new URL(referrer).hostname.replace(/^www\./, ''); } catch (e) { /* не е пълен адрес */ }
  var bare = String(referrer).trim().toLowerCase().replace(/^www\./, '');
  return /^[a-z0-9-]+(\.[a-z0-9-]+)+$/.test(bare) ? bare : '';
}
```

### Проверка след поправката — матрица на класификацията

| Вход | Очаквано | Получено |
|---|---|---|
| `?gclid=abc123` | `google_ads` | ✅ |
| `?utm_source=google&utm_medium=cpc` | `google_ads` | ✅ |
| `?utm_source=meta` | `meta_ads` | ✅ |
| `?utm_source=instagram&utm_medium=paid_social` | `meta_ads` | ✅ |
| referrer `google.com/search` | `organic_google` | ✅ |
| referrer `google.bg` | `organic_google` | ✅ |
| referrer `instagram.com` | `instagram` | ✅ |
| referrer `l.instagram.com` (пренасочващият адрес на Instagram) | `instagram` | ✅ |
| referrer `facebook.com` | `facebook` | ✅ |
| referrer `someblog.example.com` | `referral` | ✅ |
| нищо | `direct` | ✅ |
| `gclid` + referrer от Google | `google_ads` (платеното бие referrer-а) | ✅ |

**Регресия — вътрешната навигация не бива да става referral:**

| Вход | Очаквано | Получено |
|---|---|---|
| referrer = собствен домейн, пълен адрес | `direct` | ✅ |
| referrer = собствен домейн, само домейн | `direct` | ✅ |

## 24.3 Сценарии по канал

Всеки — с изчистено хранилище, тоест наистина нов посетител.

| Сценарий | Очаквано | Получено |
|---|---|---|
| Директно, без UTM | `direct` | ✅ |
| Органично от Google (referrer) | `organic_google` | ✅ *(поправено днес)* |
| Meta платено (`instagram` + `paid_social`) | `meta_ads` | ✅ |
| Referral от чужд сайт | `referral` | ✅ *(поправено днес)* |

**Важно за четенето на числата:** при **повторно** посещение без UTM
последното докосване се запазва — посетителят не се нулира до `direct`. Това е
нарочно и е правилно: човек, който се върне директно седмица след рекламата,
не е „директен“ трафик. Първото докосване също се пази отделно.
