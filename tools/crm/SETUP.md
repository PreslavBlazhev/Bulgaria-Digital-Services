# CRM — инсталация (Google Sheets + Apps Script)

Около 10 минути. След това всяка заявка от `/restaurants` влиза
автоматично като ред в таблицата, със същия Lead ID, който клиентът
вижда на страницата „Благодарим“ и който стои в имейла.

---

## Какво е това

| | |
|---|---|
| Базата | един Google Sheet, лист `Leads` |
| Входът | Apps Script Web App — `Code.gs` в тази папка |
| Кой пише | само сайтът, при потвърдено успешно изпращане |
| Кой чете | ти, в таблицата |

Web App адресът **не е тайна**. Скриптът само добавя редове и не връща
нищо от базата. Затова е безопасно да стои в кода на статичен сайт —
за разлика от API ключ на Airtable или HubSpot.

---

## 1. Създай таблицата

1. Отвори [sheets.new](https://sheets.new).
2. Кръсти я например `BDS CRM`.
3. Нищо друго — листът `Leads` и заглавният ред се създават сами при
   първата заявка.

---

## 2. Сложи скрипта

1. В таблицата: **Разширения → Apps Script**.
2. Изтрий примерния код в `Code.gs`.
3. Отвори `tools/crm/Code.gs` от проекта, копирай **всичко** и го
   постави там.
4. Запази (Ctrl+S).

---

## 3. Публикувай като Web App

1. Горе вдясно: **Deploy → New deployment**.
2. До „Select type“ натисни зъбното колело → **Web app**.
3. Попълни:
   * **Description:** `BDS CRM v1`
   * **Execute as:** `Me`
   * **Who has access:** `Anyone`
4. **Deploy**.
5. Google ще поиска разрешение — това е нормално, скриптът пише в
   собствената ти таблица. Мини през **Advanced → Go to … (unsafe)**
   и разреши.
6. Копирай **Web app URL**. Изглежда така:

```
https://script.google.com/macros/s/AKfycb.../exec
```

---

## 4. Провери, че работи

Отвори адреса в браузър. Трябва да видиш:

```json
{"ok":true,"service":"BDS CRM","sheet":"Leads","leads":0}
```

Ако видиш това — входът работи.

---

## 5. Свържи сайта

В `assets/js/app.js` намери:

```js
var CRM_ENDPOINT = '';
```

и сложи адреса между кавичките:

```js
var CRM_ENDPOINT = 'https://script.google.com/macros/s/AKfycb.../exec';
```

Празен низ значи „не е свързан“ — тогава нищо не се вика и нищо не се
чупи. Затова адресът може да се маха и връща по всяко време.

---

## 6. Тествай от край до край

```
node tools/test-restaurant-funnel.mjs --browser
```

Тестът проверява, че при попълнен `CRM_ENDPOINT` се прави точно една
заявка към него, със същия Lead ID. Той **не** пише в истинската
таблица — адресът е прихванат.

За истински тест: попълни формата веднъж на живия сайт и виж дали се
появява ред. После изтрий реда.

---

## Как се води продажбата после

Колоните, които сайтът попълва сам, свършват до `First Touch At`.
Оттам нататък пишеш ти:

| Колона | Кога |
|---|---|
| `Status` | New → Contacted → Qualified → … → Won/Lost |
| `Current Setup`, `Main Problem`, `Desired Outcome` | след discovery разговора |
| `Timeline`, `Decision Maker` | същото |
| `Next Action` | **винаги** — заявка без следваща стъпка не се затваря |
| `Follow-up Date` | **винаги**, ако статусът не е Won/Lost |
| `Last Contact Date` | след всеки разговор |
| `Proposal ID`, `Proposal Date`, `Proposal Value`, `Proposal Validity` | при изпратена оферта |
| `Deal Value`, `Close Date`, `Won/Lost`, `Client` | при затваряне |
| `Lost Reason` | при Lost — без него не се учи нищо |

Началните стойности, които скриптът слага сам:

* `Status` = `New`
* `Lead Owner` = `Преслав Блажев`
* `Next Action` = `Първо обаждане`
* `Client` = `Не`

---

## Дублирани заявки

Скриптът проверява Lead ID преди да пише. Ако някой натисне два пъти
или опита пак след мрежова грешка, вторият запис се разпознава и не
създава втори ред — връща `{"ok":true,"duplicate":true}`.

---

## Ако смениш `Code.gs`

Apps Script не публикува промените автоматично. След редакция:
**Deploy → Manage deployments → молив (Edit) → Version: New version →
Deploy.** Адресът остава същият.
